## 2. Isolation and the "I am the top window" spoof

### 2a. The two designs

Scramjet has no browser-level boundary at all. Host, controller and proxied
page share one real origin; separation is rewriting only. Its own test suite
says so (`sj/runway/src/tests/adversarial/origin-isolation.ts`: "real
separation needs a distinct browser origin per proxied site", with the
cross-site assertions marked as known failures). The spoof is: `top`,
`parent`, `location`, `eval` are rewriter UNSAFE_GLOBALS wrapped by
`$scramjet$wrap`, `.top/.parent` member reads become `Object.prototype`
accessors, `frameElement` returns the real element only if the parent carries
the client, `window.open` maps `_top`/`_parent` to frame names (so the
controller's iframe needs a visible `name`, which pages can read),
`document.referrer` is synthesised from tracked history, `MessageEvent.origin`
comes from an envelope, and host messages are delivered.

Stomp in isolated mode (`RemoteController`) has a real boundary: separate
proxy origin, `sandbox` without `allow-top-navigation`, CSP
`frame-ancestors <host>`, origin- and source-checked postMessage RPC,
transports loadable only from the proxy origin, frames addressed by index
rather than name. The spoof (`Framing.ts`, `Context.ts`, `Open.ts`,
`Navigate.ts`) covers `frameElement`, shadowed `window.name`, outer size and
screen position, routed-referrer decoding, `ancestorOrigins`, `opener`, host
messages dropped in the capture phase, `top` via the rewriter's `resolveTop`
and through destructuring, `parent` via a redefined getter, and restricted
WindowProxy stand-ins for other proxied origins that throw the real
cross-origin `DOMException`. Scramjet does none of the last five.

Stomp in same-origin mode (the live site) is "hardened": `DEFAULT_SANDBOX`
makes Chrome refuse top navigation from the frame, but the frame is still
same-origin with the host and can read its DOM. Chrome logs a warning that a
sandbox with both `allow-scripts` and `allow-same-origin` can be escaped;
that is accurate and expected.

Trust notes. Everything the rewriter decides is decided in the page realm
with the codec key in hand: a page can hand-route a URL as any kind, for
example route a child frame as a top-level document to obtain Lax cookies for
a cross-site frame (the nested route kind is a page-side decision). Isolated
mode contains the embedder's page, not its routing choices; same-origin mode
is not a security boundary at all.

## 10. What is left, by payoff

1. Import map package prefixes and scope keys: URL prefixes the browser
   matches against module URLs, which a codec-encoded route cannot keep (the
   codecs transform the whole string), so they stay as written.
2. The remaining corpus leaks (the corpus row above): the proxy origin in
   blob: URLs (every consumer would have to map a page-origin blob: URL
   back), MutationObserver records of the marker writes, and the absent
   `navigator.serviceWorker`, which is the design. Every other group is at
   zero or at probes that report the browser's own result. Outside the
   corpus: `'$s$j' in window` and `typeof Error.prepareStackTrace` are the
   two tells left (tells suite logs them).
