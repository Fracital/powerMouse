## 2. Isolation and the "I am the top window" spoof

### 2a. The two designs

Scramjet has no browser-level boundary at all. Host, controller and proxied
page share one real origin; separation is rewriting only. Its own test suite
says so (`sj/runway/src/tests/adversarial/origin-isolation.ts`: "real
separation needs a distinct browser origin per proxied site", with the
cross-site assertions marked as known failures). The spoof is: `top`,
`parent`, `location`, `eval` are rewriter UNSAFE_GLOBALS wrapped by
`$scramjet$wrap`, `.top/.parent` member reads become `Object.prototype`
accessors, `frameElement` returns the real element only if the parent carries
the client, `window.open` maps `_top`/`_parent` to frame names (so the
controller's iframe needs a visible `name`, which pages can read),
`document.referrer` is synthesised from tracked history, `MessageEvent.origin`
comes from an envelope, and host messages are delivered.

Stomp in isolated mode (`RemoteController`) has a real boundary: separate
proxy origin, `sandbox` without `allow-top-navigation`, CSP
`frame-ancestors <host>`, origin- and source-checked postMessage RPC,
transports loadable only from the proxy origin, frames addressed by index
rather than name. The spoof (`Framing.ts`, `Context.ts`, `Open.ts`,
`Navigate.ts`) covers `frameElement`, a shadowed `window.name` in the host's frame (a frame or popup the page made keeps its own), outer size and
screen position, `document.referrer` under the referring page's policy,
`ancestorOrigins`, `opener`, host messages dropped in the capture phase,
`top` via the rewriter's `resolveTop` and through destructuring, `parent` via
a redefined getter, and restricted WindowProxy stand-ins for other proxied
origins that throw the real cross-origin `DOMException`. Scramjet does none
of the last five.

Stomp in same-origin mode (the live site) is "hardened": `DEFAULT_SANDBOX`
makes Chrome refuse top navigation from the frame, but the frame is still
same-origin with the host and can read its DOM. Chrome logs a warning that a
sandbox with both `allow-scripts` and `allow-same-origin` can be escaped;
that is accurate and expected.

Trust notes. Everything the rewriter decides is decided in the page realm
with the codec key in hand: a page can hand-route a URL as any kind, for
example route a child frame as a top-level document to obtain Lax cookies for
a cross-site frame (the nested route kind is a page-side decision). Isolated
mode contains the embedder's page, not its routing choices; same-origin mode
is not a security boundary at all.

### 2c. Window references between proxied sites (window-references suite)

Every proxied site shares the proxy's one real origin, in both modes:
isolated mode puts the host on its own origin, not each proxied site. The
browser therefore never stops one proxied site from reading another's
window; the inject must hand the page a restricted stand-in (every read,
call and write throws SecurityError, `postMessage` and location writes
pass), never the raw window. The suite reaches a child of another site, a
sibling, a frameset frame, an object, an embed, an SVG document and popups
every way below, judges each reference by what it lets the page read
(document, `location.href`, `localStorage`, cookies, a function, a DOM
write) and compares it with the same pages loaded natively, in both modes
(the two modes measured the same on every path). "Raw" is the other site's
window or document as is.

Why the open ones stay open:

- A window the page reached while it was of its own origin (an about:blank
  frame or popup) is the browser's WindowProxy, which keeps its identity when
  it navigates (window-identity relies on that for `event.source === popup`).
  Natively the browser checks every access against the document the window
  shows now; here nothing does, and the inject cannot take back an object
  the page holds. Only a real origin per proxied site, or a fresh browsing
  context for every cross-site navigation of a window someone holds (which
  breaks identity and cannot be done for redirects or popups), closes it.
- `Array.prototype` methods called on a window and object spread read the
  window's indices natively. Wrapping every array method would tax every
  array call; spread could be rewritten (`{ ...$s$j.spread(x) }`) for a cost
  per spread.
- `Document` has `[LegacyOverrideBuiltIns]`: a named iframe is an own
  property of the document that nothing can shadow or redefine while it
  exists. Only virtualising frame names (the real name attribute and
  browsing context name obfuscated, link targets and `window.name` mapped)
  would close it.
- (Closed.) A fresh about:blank frame's realm ran no Stomp until a mediated
  read injected it, and a literal name or a native copy is no such read. A
  frame that stays on about:blank (no src, srcdoc or data) is now injected
  as it connects: from the insertion hooks and markup setters, from the
  preamble of each parser-inserted inline script (the parser runs it inside
  the write that made the frame, before any observer hears of it), and from
  a document observer, at the cost of a walk of the window's children per
  insertion. A frame on its way to a document is left to that document's
  own shell: the browser keeps the Window for a same-origin document, which
  would otherwise run the parent's client (eight suites regressed when
  every frame was injected). A client injected into an about:blank that a
  later document keeps (a contentWindow read early) now posts through its
  window's own postMessage, or its messages named the framing page as their
  source.

## 10. What is left, by payoff

State as of 2026-11-08, the corpus first (both demo modes together, failing
checks per group out of 180 at the start): protos 0, eval 0, globals 0,
workers 0, attrs 0, scripts 2, urls 2, frames 4, messages 4; 12 in all, down
from 14 when this section was last written.

1. Stays out by design, documented as such:
   - `navigator.serviceWorker` is absent in proxied pages by default (urls,
     2 checks): a page that could register a worker on the proxy origin
     could serve itself. `serviceWorkers: true` gives pages emulated ones
     instead, which never register anything real (docs/service-workers.md).
   - Eight probes report the browser's own result, not a leak: the window
     `window.open('javascript:')` returns (scripts 2), the window from
     `window.open('about:blank')` and a probe's own source text in
     `innerHTML` (frames 4), a sloppy-mode detached call that cannot throw
     and the child window a parent sees as `event.source` since the
     postMessage rewrite (messages 4).
   - Same-origin mode is hardening, not a boundary (section 3); the
     RemoteController mode is the boundary.
   - Another proxied site's window is still reachable raw through a window
     the page held while it was of its own origin, native copies of a
     window's children, a document's named iframe, and (from a frame of
     another site) an uninjected about:blank frame of its own reached by a
     literal name or a copy (section 2c). Literal indices and named access
     on the window are routed since 2026-11-09.
   - Import map package prefixes and scope keys stay as written: URL
     prefixes the browser matches against module URLs, which a codec-encoded
     route cannot keep.
   - A synchronous XHR that needs the network deadlocks only with an in-page
     transport; the transport worker (the default for a descriptor) is the
     answer, not a change to the sync bridge.
2. One tell left, recorded by the tells suite, not compared: a page that
   names the access API reads it (`window.$s$j`, `window[name]`,
   `typeof $s$j` are an object, natively undefined; the client's name
   reads undefined, the rewriter routes it). Hiding it means routing reads
   of the name through the access API without catching the rewriter's own
   references to it. The two tells this item listed are closed since
   2026-11-10, asserted against native in both modes (tells suite): the
   `in` operator no longer finds a helper name (the rewriter hands an `in`
   whose key is not a literal, or is a helper's name, to the access API's
   `has`; no cost measured on the 46 MB rewriter corpus, about 2 ns per
   `in` at run time), and `typeof Error.prepareStackTrace` is `undefined`
   (section 7). The source of a rewritten function reads as the page wrote
   it since 2026-11-09 (function-source suite).
3. Pending on a branch (review/multi-controller, second pass): several
   controllers per directory, with the cookie jar, HTTP cache and storage
   shared per scope and a redirect for a stale address.
